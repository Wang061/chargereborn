## 0. 一句话

相机留在臂上但只在**固定观察位姿**取帧，按该视角做一次性 `像素→台面mm` 单应性标定；Brain 端跑**几何正确的逆运动学**（修掉 OpenMV 参考里的 `theta6` 放大 bug）把电池的**绝对台面坐标**解成 4 个舵机 PWM，经**已验证可动的裸协议捆绑帧**发给 KM1，配合腕角对齐与夹爪开合，完成"识别→抓取→移到刀口→切割→放回→回观察位"闭环。质量优先——丢弃旧方案里导致低夹取成功率的开环偏移猜测与迭代伺服，改用标定过的绝对定位 + 抓取前多帧复检。

## 1. 背景与根因（为什么不照搬 OpenMV 旧方案）

### 1.1 现状（master，已上板）
- Brain 边缘 AI 主轴已打通：ESPDet-Pico 18650 检测器（float mAP50 0.96，板上 int8+letterbox ~3.5Hz），`components/ai` 输出 `ai_result_t`（含框中心、长轴 `angle_deg`、各向异性 `anisotropy`）。
- `components/armlink`（Phase 1，2026-07-02 硬件验证）：从检测结果选最佳电池框 → `arm_target_t`（像素中心 + 角度）；`/arm_target` 端点；裸腕舵机测试帧（`{#004P..T..!}`，真机物理验证可动）；`/arm_test`、`/arm_auto` 端点；运行时 `s_auto_send` 开关默认关。UART1 TX=GPIO1 → KM1 OpenMV 口 RX2(GPIO41)，已接线。
- **关键事实（CRASH_SIGNATURES 2026-07-02）**：真机 KM1 固件**没有可用的 `$KMS:` 运动学自解算**（COM4 直连实测：sscanf 不匹配、无响应）。只有裸舵机帧 `{#00xPppppTtttt!}` 与 `$DST:` 系列真机可动。

### 1.2 蓝图旧假设已失效
- `PROJECT_BLUEPRINT_GOLD.md` §1.3 与 `BUILD_STEPS_DETAILED.md` Ch4 假设"Brain 发坐标 → Steward 自做 IK（ESP-NOW）"。此路因 §1.1 的 `$KMS:` 事实**已死**。
- 新形态：**IK 必须在 Brain 侧算**，发裸协议 PWM。这恰好就是 OpenMV 侧 `kinematics.py` 一直在用的架构（它在视觉侧算完 IK，发 `{#000P..!#001..!#002..!#003..!}` 捆绑帧）——即 Brain 复刻 OpenMV 的角色。ESP-NOW 不再需要，用现有单向 UART。

### 1.3 旧方案低夹取成功率的两个根因（本轮从根上换掉）
1. **底座角公式 bug**：OpenMV `kinematics.py:45` 用 `theta6 = atan(x/y) * 270/π`，比正确的弧度→度（`* 180/π`，见真机 `.ino`）**放大 1.5 倍**；两版 PWM 映射相同（270° 舵机）。结果底座转角系统性偏大 50%，电池在正前方（x≈0）无误差、越偏离中线抓得越偏。与"正中能夹、偏一点抓空"症状吻合。→ **本轮 IK 用几何正确版。**
2. **开环偏移猜测**：`batteryTask.py` 是 eye-in-hand——先把电池在相机画面里挪到中心，再"往前伸固定 `pickup_forward_offset=100mm`"够真实位置；本想用 `pickup_calib_y_near/far` 两锚点插值补偿，**但两个值都填了 100（等于放弃标定）**。居中在相机里 ≠ 夹爪在电池上。→ **本轮改标定过的绝对定位，不猜偏移。**

### 1.4 用户约束（本轮决策依据）
- **质量优先**（用户明确）：不复现历史低成功率；宁可多花时间标定换准度。
- **相机在臂上，但定位只在固定观察位姿做**（用户方案）：臂每轮回到同一观察位，相机视角可复现 → 按该视角标定一次 px→mm，等效 eye-to-hand 精度；同时保留"臂带相机去看切割处复检"的能力（stretch）。
- **demo 终点 = 全流程含切割**（用户选）。
- **安全分级干跑→升级**（用户选）。

## 3. 架构与数据流

### 3.1 数据流
```
[观察阶段] 臂回固定观察位姿 (observe_x,y,z + 腕中位, 同方向进入消回差) → 停稳延时
    → OV2640 取帧 → ESPDet 检测(已有 components/ai)
    → 多帧平均 + 抖动门(N帧, 借鉴 OpenMV final_verify_pose)
    → 像素中心(cx,cy) + 长轴角(angle_deg)
[定位阶段] (cx,cy) → 单应性 H(NVS 读) → 台面绝对 (mm_x, mm_y)
    → 图像角 → 世界角(过 H 线性部分)
[解算阶段] (mm_x, mm_y, pick_z) → Brain IK(components/kinematics, 修 theta6)
    → 4 舵机角 → 4 PWM; 世界角 → 腕舵机(#004) PWM; 夹爪(#005) 开/合 PWM
[执行阶段] armlink 编码裸协议捆绑帧 {#000P..T..!#001..!#002..!#003..!}
    → UART1(GPIO1) → KM1 OpenMV口 RX2(GPIO41) [已验证链路]
[抓取序列] 目标正上方悬停 → 预抓高度 → 腕#004 对齐长轴 → 最终下降
    → 夹爪#005 闭合 → 抬起(carry_z) → 移刀口 → 切2次 → 放回 → 开爪 → 回观察位
```

### 3.2 组件划分（遵循项目组件化/分层规则）
- **`components/kinematics`（新）**：纯逆运动学数学，无硬件依赖。`kin_setup(L0..L3)`、`kin_solve(x,y,z,alpha, out_pwm[4])`（返回可达性错误码 0-7）、`kin_move_best(x,y,z, out_pwm[4])`（扫描 alpha 找最优俯角）。可在 host 或板上独立自检（对拍参考实现）。**这是驱动/业务分层里的"算法层"。**
- **`components/armctrl`（新）**：抓取-切割状态机（FreeRTOS 任务）。消费 `ai_result_t` + `kinematics` + `armlink`，持有观察位/抓取/切割时序与标定后的常量。状态机 = 业务层。
- **`components/armlink`（改）**：保持"选最佳目标 + 传输层"职责。新增：4 舵机**捆绑帧编码**（`armlink_encode_arm_frame(pwm[4], move_ms, out, n)`）、单舵机帧编码复用现有 `armlink_send_wrist_pwm` 思路。`armlink_update_from_ai` 的自动路径改为**不再直接发**（由 armctrl 状态机统一驱动，避免每帧乱发）。
- **`components/net`（改）**：新增 `/arm_calib`（写入单应性 H + 观察位参数到 NVS）、`/arm_run`（启动/停止一轮抓取循环）、`/arm_grade`（设置当前允许的安全级 G0-G4，联锁）。沿用 httpd `stack_size=8192`（CRASH_SIGNATURES 已记）。
- **NVS（新命名空间 `armcal`）**：H[9]、观察位姿、连杆 L0-L3、腕角 K/零位、夹爪 PWM、刀口坐标。未标定则 `armctrl` 拒绝进自动模式。

## 4. 定位与标定（质量核心）

### 4.1 观察位姿
- 开机与每轮循环，臂回固定 `(observe_x, observe_y, observe_z)` + 腕中位。
- **总是从同一方向进入观察位**（先到中转点再到观察位）以消舵机回差；停稳延时（`>= move_time + settle`）后才取帧。
- 观察位必须让相机视野覆盖整个工作台放置区，且与标定时完全一致（同一组舵机 PWM）。

### 4.2 单应性标定
- 台面已知 mm 位置摆 **6–9 个标定点**（比蓝图的 4 点多，最小二乘更稳、抗单点误差），从 `/detect` 读各点像素中心，PC 端 python（`cv2.findHomography`）求 3×3 单应性 H → 经 `/arm_calib` 写入 NVS。
- **未标定时 `armctrl` 自动模式拒绝启动**（安全联锁，日志明示）。
- 像素→mm：`w = H6·px+H7·py+H8; mm_x=(H0·px+H1·py+H2)/w; mm_y=(H3·px+H4·py+H5)/w`。

### 4.3 视差修正（旧方案没做、零成本消一个系统误差）
- 标定点**垫高 9mm**（18650 半径），让 H 直接映射到"电池中轴平面"而非台面平面 → 省掉视差换算，消掉 ~5mm 级系统误差。
- 若换其他直径电池，中轴高度随之调整（本轮只 18650，固定 9mm）。

### 4.4 腕角
- 图像长轴角 → 世界角（过 H 的线性/旋转部分换算）→ 减去抓取点的方位角（底座朝向）= 腕舵机目标角。
- PWM = `1500 + deg × 5.6`（继承 OpenMV `wrist_pwm_per_degree=5.6`、中位 1500、限位 500-2500）；**K 与零位在 G1 干跑实测复核**（旧值仅作起点）。

## 5. 逆运动学移植（修 bug，不照抄）

### 5.1 公式
- 用真机 `.ino` 的几何解（law-of-cosines 平面 2 连杆 + 底座旋转 + 腕俯仰），`theta6 = atan2(x, y) * 180/π`（**弧度→度，绝不用 OpenMV 的 270/π**）。
- Alpha（爪-平面夹角）从 0° 扫到 -135°，1° 步长，取能得到可达解的**最负 Alpha**（"3 号舵机与水平最大夹角"），照搬参考策略。
- 舵机角→PWM 映射照搬（270° 舵机，`1500 ± 2000·angle/270`），四路符号按参考。

### 5.2 连杆常量（两源冲突，不猜）
- `.ino`：L0=100, L1=105, **L2=75, L3=180**；OpenMV `kinematics.py`：L0=100, L1=105, **L2=88, L3=155**。**冲突。**
- **裁决：卷尺实测真臂四段长度**（~10 分钟），作为唯一真值写入 NVS。G1 干跑时命令已知点、尺量末端实际到达位置做闭环验证；不匹配就调常量重验。

### 5.3 上板自检
- 固件启动打印一组预算好的 IK 测例（几个 (x,y,z) → 期望 PWM），对拍 PC 参考实现；不匹配则日志报警并拒绝进自动模式。

## 6. 抓取-切割状态机

### 6.1 继承 OpenMV 已验证的时序骨架与常量（真机跑通过的部分）
- 时序：目标上方悬停(1500ms) → 预降(1200) → 最终下降(1400) → 夹爪闭合(800ms) → 抬起 carry_z(1400)。
- 高度：`approach_z=70`（安全悬停/接近高度，即旧 `search_z`——本轮无扫描搜索动作，此值只作"下降前的安全高度"）、`carry_z=120`、`place_z=3`（起点值，G 级验证期实测微调）。
- 刀口：`blade_x=145, blade_y=75, blade_safe_z=100, blade_contact_z=40, cut_offset_x=12, cut_times=2`（起点值）。
- 夹爪：`#005`，开=800、合=1700、800ms（起点值，**G1 用户手上验证**——"夹爪能动但不知 PWM"清单里的坑，两个数就是答案）。
- 腕：`#004`，中位 1500。

### 6.2 砍掉低成功率的部分
- 迭代图像伺服对准（eye-in-hand 挪臂居中）→ **删**，改绝对定位。
- `pickup_forward_offset` 及其未标定的两锚点插值 → **删**。
- 颜色 blob 检测（`battery_thresholds`/`shape_candidate_thresholds`）→ **删**，用神经网络检测框（我们有更可靠的 `angle_deg`/`anisotropy`）。

### 6.3 加质量三件套
1. **观察位多帧平均 + 抖动门**（借鉴 `final_verify_pose`）：连续 N 帧，中心跳动 > 4px 或角度跨度 > 12° 就不动手、重采。
2. **下爪前正上方悬停**：臂先到目标正上方悬停，G 级验证期此时**人可急停**；确认无误再下降。
3. **不可达即安全停**：任一 `kin_move_best` 返回不可达（错误码非 0）→ 立即安全停 + 回观察位，不硬走、不发越界 PWM。
