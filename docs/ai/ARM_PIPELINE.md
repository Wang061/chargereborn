# 机械臂自动抓取-切割 · 复现与运行手册 (ARM_PIPELINE)

> ChargeReborn Phase 2：Brain(ESP32-S3) 用视觉检测 18650 → 逆运动学解算 → 裸协议帧驱动 KM1 机械臂，
> 完成 识别→抓取→切割→放回→回观察位 的闭环。本文是上板复现与操作手册；物理量待 D2+ 硬件 session 实测填表。
> 相关：设计 spec `docs/superpowers/specs/2026-07-02-phase2-ik-autograsp-design.md`、安全 `docs/ai/SAFETY.md`、坑 `docs/ai/CRASH_SIGNATURES.md`。

## 1. 架构与数据流

三层组件，职责单一、可分别 host 单测：

| 层 | 组件 | 职责 | 依赖 |
|---|---|---|---|
| 运动学 | `components/kinematics` | 纯 IK（law-of-cosines 平面 2 连杆 + 底座旋转 + 腕俯仰），无 ESP 依赖 | 无 |
| 状态机 | `components/armctrl` | 观察→定位→抓→切→放 时序 + 安全联锁 + 运动原语 | kinematics / armcal / armlink_frame / armlink |
| 传输 | `components/armlink`(含 `armlink_frame`) | 选最佳电池目标 + 缓存 + 帧编码 + UART sink | armlink_uart |
| 标定 | `components/armcal` | 单应性 px→mm、参数集 NVS 持久化 | nvs |

**数据流（单一驱动路径）**：

```
相机→ai 检测(每帧) → armlink_update_from_ai(选最佳电池框, 只更新 s_last 缓存)
                                   │
            armctrl_task ─ go_observe() 回观察位
                         ─ acquire_pose() 连续 5 帧, 中心抖动>4px 或 角度跨度>12° 判失败重采
                         ─ homography_apply(H) px→台面mm + homography_angle 长轴角→世界角
                         ─ kin_move_best() IK 解 4 舵机 PWM(扫 Alpha 0→-135 取最负可达解)
                         ─ armlink_encode_arm_frame() 裸协议捆绑帧
                                   │
                         armlink_uart_send() → UART1(TX=GPIO1) → KM1 RX2(GPIO41)
```

- **捆绑帧格式**（4 主关节一帧）：`{#000PxxxxTxxxx!#001...!#002...!#003...!}`
  = #000 底座旋转 / #001 大臂 / #002 小臂 / #003 腕俯仰；腕旋转 #004、夹爪 #005 走单舵机帧 `{#0xxPxxxxTxxxx!}`。
  **✅ 捆绑帧真机验收通过（2026-07-03 G1 步 2）**：COM6 直发 62B 捆绑帧，KM1 逐字节回显、**四关节同动**——多段一帧解析在真机固件上成立，无需拆单帧回退。（此前 Phase 1 只验过单舵机帧。）
- **唯一驱动者 = armctrl 状态机**。Phase 2 起 `armlink_update_from_ai` 只更新目标缓存，**不再直接发帧**（旧的"每帧自动发坐标"路径已中和）。单舵机/单臂手动联调走 `armctrl_move_servo`/`armctrl_move_arm`（供状态机与联调的低层原语，见 `armctrl.h`）；原独立的 `/arm_test` 手动测试端点已随 G 级分级一并退役。
- **⚠ `$KMS:x,y,z,t!` 自解算在真机 KM1 固件上未实现**（COM4 直连实测 sscanf 不匹配、两端无回应，见 `CRASH_SIGNATURES.md`）。**唯一可动的驱动 = 裸协议 `{#idxPpwmTms!}`**；IK 在 Brain 侧算完直接下发各舵机 PWM，不依赖 KM1 自解算。

## 2. 安全模型

### 2.1 三重联锁（全绿才动手）

`armctrl_task` 主循环执行任何运动前，三个条件缺一不可：

1. **编译期** `CONFIG_ARMLINK_UART_ENABLE` —— 未开则所有 `armctrl_move_*` 是空操作（`ESP_ERR_INVALID_STATE`），固件不驱动任何舵机。
2. **运行时 run**（`/arm_run?on=&cont=`，`s_run`，默认 **off**）—— 抓取循环总开关；单轮模式每轮结束自动 `s_run=false`，连续模式（`cont=1`）持续循环直到手动停止/急停/连续 3 次未获取到稳定目标。
3. **IK 自检 + 标定 valid** —— 启动时 `kin_selftest()` 对拍内嵌 golden PWM，失败 `s_ik_ok=false` 禁用自动模式；`armcal_load` 无有效标定则 `s_cal.valid=false`，未标定时任何 `run` 请求直接被拒。运动原语层（`armctrl_move_arm`/`armctrl_move_servo`）额外做"未标定绝不发字节"的最后一道兜底，即使联锁被绕过也不会发出真实坐标。

连续模式的防重抓排除表在并发 `/arm_run` 请求下是尽力而为的(表本身只由 armctrl 任务读写、跨任务只传指针拷贝,无内存安全问题;但运行中重复发 `on=1` 可能清掉/漏记个别排除点,最坏一次重抓,下轮自纠)。

### 2.2 急停

- **软件急停**：`/arm_estop?on=1` → `armctrl_estop()` 立即发送 `$DST:0!`（唯一真机验证过的急停串，见 `docs/ai/CRASH_SIGNATURES.md` 2026-07-02）→ 停止循环 → 锁存 `s_estop`；锁存期间任何 `run` 请求都被拒绝，需 `/arm_estop?on=0` 显式清除才能恢复。
- **物理急停**：断动力电（首选，任何时候都可用，不依赖固件状态）。
- 每个运动原语（`armctrl_move_arm`/`armctrl_move_servo`）内部都检查 `s_estop`，急停触发后即使当前序列还在执行中，下一个原语调用也会立即短路不发送。

### 2.3 失败回退：绝不在刀口旁松爪

- **切割失败** → **保持夹持撤离**：先尽力撤到 `blade_safe_z`（返回值有意忽略，撤离优先），再 `go_observe_ex(false)` **不开爪** 回观察位，半切开的电池夹着等人工取回。
- **抓取失败** → `go_observe()` 正常开爪回观察位、`s_run=false`。
- 复位默认安全位：腕中位 #004=1500、开爪 #005=开、抬到 `carry_z`。

## 3. 标定流程（操作手册级）

### 3.1 观察位

- **相机装在臂上（eye-in-hand），只在观察位取帧**——H 绑定的是"观察位这一组舵机 PWM 下的相机视角"，等效 eye-to-hand（spec §1.4/§4.1）。
- 定义：正前方 (`observe_x`,`observe_y`,`observe_z`) 俯视电池台面。**G1 定稿 (0,100,70)**（2026-07-04：即 OpenMV 原厂 Home 位，alpha=-77°；对比试过 (0,130,120) 视野太靠前、(0,100,50)/-89° 近垂直，用户实测本位画面覆盖最好）。相机前视特性：视野中心在臂尖前方约 80–130mm（OpenMV `pickup_forward_offset=100` 同源），标定点带 y=150–210 落在视野内。
- 要求：每轮**从同一方向进入并停稳**（先中转点 `(0, observe_y, carry_z)` 再到观察位，消舵机回差）；`acquire_pose` 连读 5 帧，抖动超门限（中心 4px / 角度 12°）就不动手、重采。

### 3.2 台面标点（把 IK 坐标系画到台面上，两段式）

**标点的坐标系必须与固件 IK 是同一个**：原点 = 底座旋转轴心在台面的投影；y = 底座舵机 #000 打中位（PWM 1500）时臂指向的正前方；x 与 y 垂直。y 轴方向只有臂能动了（G1）才能校准，所以标点横跨"现在"与"G1"两段。

**第一段（现在就能做）**：

1. **固定底座**：螺丝、夹具或热熔胶，把底座与台面的相对位置定死。从这一刻起底座不许再挪——原点长在它身上。
2. **定原点**：找底座旋转舵机的轴心，向台面做垂直投影。实用做法：从底座外壳两侧各量一次"外缘到轴心"取中，在台面正前方贴美纹纸胶带画出原点估计位置。**原点每偏 1mm，以后所有目标系统性偏 1mm**，直接吃精度预算，尽量 ±1mm 内。
3. **备工具**：卷尺或直钢尺、细头记号笔、美纹纸胶带（画在胶带上，撕了能重来）、A4 纸或三角尺（当直角用）。

**第二段（G1 臂能动之后，y 轴方向必须用臂本身校准）**：

4. **校 y 轴**：给 #000 发 1500（单舵机帧，G1 手动联调即可发），臂停稳后沿臂在台面上的投影从原点画一条直线——这就是 y 轴。**不能目测猜"大概正前方"**：方向歪 5°，150mm 远处就是 13mm 横向误差，直接爆预算。
5. **画 x 轴**：过原点作 y 轴垂线（A4 纸直角对齐）。
6. **确认 x 正方向**：让臂走一个 IK 点（如 (40,105)），看末端往哪边偏——臂偏向的那一侧 = x 正方向。**别猜**：舵机装向决定符号，猜错了整个标定镜像。
7. **画点（先横线后偏移）**：垂直 y 轴画三条横线 y=80 / y=105 / y=130；每条横线上从 y 轴向两侧量 x 偏移，得 8 点 `(-60,80) (0,80) (60,80) (-60,130) (0,130) (60,130) (-40,105) (40,105)`。每点画成**十字**，臂长比电池直径长（如 4cm）——电池压上去两端还露着，方便对中。十字用细线画，检测模型不会误检；但避免大块深色图案。
8. **自检点距**（现在花 1 分钟，比等残差自检抓错便宜）：(-60,80)↔(60,80) 应 120mm；(0,80)↔(0,130) 应 50mm；对角 (-60,80)↔(60,130) 应 130mm（勾股 120-50-130）。±1~2mm 合格。
9. **确认覆盖**：臂停观察位，`/detect` 视野要罩住全部 8 点，且都在臂可达范围内。不满足就改 `KNOWN_MM`——原则：盖住真实抓取区、≥6 点、别共线，**脚本里的表与台面实际画的必须一致**。

### 3.3 单应性标定（px→台面 mm）

**前提（顺序硬约束，相机在臂上决定的）**：

- **标定必须在 G1 之后**——标定时臂要由固件驱动到观察位并**全程保持**（同一组舵机 PWM、同方向进入、舵机上电保持力矩）；G0 不发 UART 到不了，手摆臂摆不出可复现 PWM 位姿。
- **标定前怎么让臂动（鸡生蛋解法）**：未标定时固件联锁强制干跑（armctrl 发不出帧），G1/标点第二段/标定摆位一律走 **COM4 直连 KM1 发裸帧**；帧用 `scripts/ik_preview.py` 算（与固件同一 IK 逐行镜像，`--selftest` 对拍固件 golden 锚点；`--observe` 直接吐中转点+观察位两帧）。摆观察位的完整顺序照 `go_observe`：`{#005P0800T0800!}` 开爪 → `{#004P1500T0600!}` 腕中位 → 中转帧 → 观察位帧（相机在臂上，腕不回中位姿就不可复现）。标定 POST 后联锁解除，驱动权交还 armctrl，COM4 退役。
- 标定前**定稿并冻结**：观察位参数、相机在臂上的安装（刚性固定不许碰）、底座↔台面相对位置。三者任一变动 = H 作废重标。
- 标定后建议做**复现性检查**：台面留一颗电池不动，让臂离开观察位再回来，`/detect` 像素中心漂移应 ≤ 几 px，超了说明回差没消干净。

步骤：

1. **平放不垫高**：标定用**真电池平躺**、轴心对准台面标记点即可。原理：单应性只对一个平面精确成立，**标定面必须与运行时被测特征（电池轴心）同高度**；平躺电池轴心天然在 z=直径/2（当前 φ14×51 实测电池 = 7mm），与抓取时同一平面，视差自动被 H 吸收。**垫高反而有害**——会把标定面抬到 2×半径，与运行时差出一个半径的视差（估算可达 ~5mm 系统偏移）。只有当标定基准是**贴台面的平面标记**（纸印圆点等，特征在 z=0）时，才需要把标记垫高半径；旧文档"垫 9mm/7mm"即混淆了这两个场景。
2. 臂停观察位保持不动，板子进 SoftAP（`192.168.4.1`），`/detect` 出框且视野覆盖整个抓取区。
3. 跑 `scripts/calibrate_homography.py`（`.venv-tools`：`pip install opencv-python numpy requests`）：
   - 交互式，按提示把电池摆到台面 8 个已知 mm 点（`KNOWN_MM`，按实际工作台改，≥6 点最小二乘更稳），逐点回车采集像素中心（取最高分框）。
   - `cv2.findHomography` 求 H → **残差自检**：逐点打印 `est(mm) err(mm)`，残差应 ≤ 几 mm，超了检查垫高/摆位/点数。
   - 确认后 `POST /arm_calib`（body = `H0,H1,...,H8` 九个浮点）→ 板子 `armcal_save` 写 NVS，置 `valid=true`，并 `armctrl_reload_cal()` 让**运行中的控制器在空闲时自动重载新标定（无需重启）**——重载只在状态机空闲分支发生，绝不打断进行中的抓取序列。
4. `GET /arm_calib` 可回查当前 H 与观察位、`valid` 状态。**未标定（valid=false）自动模式拒绝启动**。

### 3.4 G1 当日操作清单（严格按序，用户在场、手不离电源开关）

> 关键认知：未标定时固件联锁**强制干跑**（§2.1 第 3 条），所以 G1 绝大部分动作走 **COM4 直连 KM1**（帧由 `scripts/ik_preview.py` 算）；Brain 侧在标定 POST 前唯一能实发 UART 的路径是 `/arm_test`（#004 摆动，不受标定门限，专供链路验证）。"G1=UART 首次实发"指的是字节首次上线，两条线都要验：**COM4→KM1**（主力）与 **Brain GPIO1→KM1 GPIO41**（`/arm_test`）。

**0. 上电顺序与初始安全**：桌面无刀、无电池；先 Brain 上电稳定（联锁默认 run=off，线上静默）；再 KM1 逻辑电；最后舵机动力电——**KM1 上电舵机是否跳动未知**，上电瞬间人手扶住可随时断电。
**1. 行程仲裁（第一项，其他一切 IK 动作之前）**：COM4 发 `{#000P1500T1000!}` 停稳 → 在舵盘/臂上贴指针（吸管/牙签），纸上标起点 → 发 `{#000P2000T1500!}` → 量转角。**67.5°⇒270° 舵机（假设成立，继续）；45°⇒180° 舵机 → 全线停下回来找我**——不只 IK 系数要 ×1.5，`kin_selftest` 内嵌 golden 锚点也编死了 270° 映射，须一并重算重烧，否则板上自检会反过来拦你。用 #000 仲裁是因为底座旋转在水平面，无重力负载、不会砸台面。
**2. 捆绑帧解析验收（新风险，真机从未验证过多段一帧）**：COM4 发一条 ik_preview 算出的 4 关节捆绑帧（如 `--observe` 的中转帧），**看 4 个关节是否全动**（COM4 回显也可对照）。只动第一段 ⇒ 真机不支持捆绑 ⇒ 停下回来找我改成拆单帧连发。
**3. Brain 链路验字节**：KM1 侧开 COM4 监视 → Brain 网页点"机械臂测试帧"（`/arm_test`）→ COM4 应回显 3 条 #004 帧（KM1 收到什么就回显什么，**等效逻辑分析仪**且更强：证明的是"KM1 解析到了"）。
**4. 标点第二段**（§3.2 步 4–9）：`{#000P1500T1000!}` 画 y 轴 → 直角画 x 轴 → COM4 发 `ik_preview.py 40 105 50` 的帧，末端偏向侧=+x → 画 8 点 → 勾股自检 120/50/130。
**5. IK 定位精度**：挑 3–4 个已画的点（含最远点），逐点 COM4 发帧，卷尺量末端投影与十字的偏差，**≤5mm 过线**。超了先查：原点标定偏差 / L3（抽查：夹上电池重量一次腕轴心→电池轴）/ 舵机中位偏移。
**6. 夹爪与腕**：#005 先小步试方向（800↔1700 连方向都未验证过）：从当前值往一侧走 100µs 看开还是合；确认方向后定"开到位/夹住 φ14 不打滑"两个 PWM。#004 发 ±150µs 应转 ≈27°（k=5.6 复核）。pick_z 从 30mm 起逐次下探找"爪心正好卡电池轴心（≈7mm）"的 z。
**7. 机械参数代码定稿**：把 5/6 步产出（夹爪 PWM、pick_z、观察位微调、若 L3 修正）写回 `armcal.c` 默认值 → **重新 build+flash**（NVS 冻结坑纪律：这一步必须在 POST H 之前，见 §5）。
**8. 摆观察位 + 单应性标定**（§3.3）：COM4 按 `go_observe` 顺序摆位（开爪→腕中位→中转→观察位，`ik_preview.py --observe`）→ 跑 `calibrate_homography.py` 采 8 点（电池平躺不垫）→ 残差 ≤ 几 mm → **最后才 POST H**。
**9. Brain 首次实发闭环**：POST 后联锁解除 → 网页 G 级设 1、点启动 → armctrl 应自主走"回观察位→定位→（G1 慢速）"，观察一轮。此后 COM4 退役，进 G2。

## 5. 已知坑（照抄事实，防回归）

- **OpenMV theta6 放大 1.5× bug（已修）**：OpenMV 版底座旋转角 弧度→度 误用 `atan2(x,y)*270/π`（应为 `*180/π`），放大 270/180 = **1.5×**。本项目 `kin_solve` 用 `*180/π`；`kin_selftest` 内嵌 Anchor B（x=120,y=120,z=40 期望 pwm0=1166，bug 会得 1000）**对拍防回归**，失败即拒绝进自动模式。
- **`$KMS:` 真机无效**：KM1 固件未实现 `$KMS:x,y,z,t!` 自解算 → 唯一驱动是裸协议帧（见 §1、CRASH_SIGNATURES）。
- **视差**：标定面必须与运行时被测特征（电池轴心，z=直径/2）**同高度**。用真电池标定 → **平放不垫**（轴心天然同面）；用平面标记标定 → 垫高半径。曾错写成"给电池垫半径"（双重计算，会引入 ~5mm 系统偏移），已纠正（见 §3.3）。
- **舵机回差**：进观察位/关键位必须**同方向进入 + 中转点**过渡，否则重复定位有回差散布。
- **httpd `max_uri_handlers` 默认 8 不够**：已注册 11 个 URI（root/status/capture/detect/arm_*），现设 **16**；`stack_size` 默认 4096 会被 `detect_get` 的 `buf[1536]+ai_result_t` 撑爆，现设 **8192**（见 CRASH_SIGNATURES）。
- **armcal NVS 冻结坑**：`POST /arm_calib` 的 handler 是"armcal_load（NVS 或默认）→ 只改 H → **整个 armcal_t 整包写 NVS**"。此后每次开机 `armcal_load` 都以 NVS blob 为准，**再改代码里的默认值（夹爪/高度/连杆等）重新烧录也不生效**（被 NVS 旧包覆盖）。纪律：**G1 把机械参数在代码定稿之后，最后才 POST H**。搞反了的逃生通道：递增 `armcal.h` 的 `ARMCAL_MAGIC` 使旧 blob 作废回到代码默认（代价：H 丢失需重标）。
- **`-Werror=misleading-indentation`**：工程开了该告警即错，多语句紧跟 `if`/`for` 后缩进必须规范，否则 build 红。

## 6. HTTP 端点速查（SoftAP `192.168.4.1`）

| 端点 | 方法 | 作用 | 返回 |
|---|---|---|---|
| `/detect` | GET | 读最近检测缓存（不触发推理，handler 轻）；`boxes[]` 只含 ≥0.40 高分框（弱框只喂跟踪器不上叠加） | `{w,h,infer_ms,n,boxes[...]}` |
| `/arm_target` | GET | 读跟踪器滤波后的机械臂目标缓存 | `{valid,stable,coasting,cx,cy,angle_deg,score,w,h,frame_id}` |
| `/arm_calib` | GET | 查当前 H + 观察位 + valid | `{valid,H[9],observe[3]}` |
| `/arm_calib` | POST | body=`H0,...,H8` 九浮点，写 NVS 置 valid，并触发 armctrl 空闲重载（免重启） | `{saved:bool}` |
| `/arm_run` | GET | `?on=1|0&cont=1|0` 启停抓取循环；`cont=1` 完整循环后不停,继续下一轮 | `{running:bool,cont:bool}` |
| `/arm_estop` | GET | `?on=1` 立即急停并锁存(发 `$DST:0!`)；`?on=0` 清除锁存 | `{estopped:bool}` |

操作页（`/` root）有**连续模式勾选 + 抓取启动/停止 + 急停**按钮，直连 `/arm_run`、`/arm_estop`。
